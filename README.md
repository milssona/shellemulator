# Эмулятор языка оболочки ОС

Практическая работа по дисциплине "Конфигурационное управление", вариант 11.

## 1. Общее описание

Программа имитирует работу в командной строке UNIX-подобной ОС. Эмулятор написан на Python 3
(версия 3.8 или новее) и работает в графическом окне на библиотеке tkinter, которая входит
в стандартную поставку Python. Сторонние библиотеки не нужны.

Основные возможности:

- заголовок окна строится из данных реальной ОС: `Эмулятор - [имя_пользователя@имя_компьютера]`;
- аргументы команд можно писать в одинарных и двойных кавычках;
- виртуальная файловая система (VFS) загружается из ZIP-архива и целиком хранится в памяти,
  архив не распаковывается на диск и не изменяется;
- двоичные файлы выводятся в формате base64;
- при запуске можно выполнить стартовый скрипт, он останавливается на первой ошибке;
- поддерживаются команды ls, cd, cat, head, touch, date, vfs-init, help и exit.

Содержимое репозитория:

- `src/main.py` - окно, разбор параметров и команды;
- `src/vfs.py` - виртуальная файловая система;
- `tests/` - автоматические тесты;
- `tools/make_vfs.py` - создание тестовых ZIP-архивов;
- `scripts/` - стартовые скрипты эмулятора (`.txt`) и скрипты запуска для проверки (`.bat`);
- `run.bat` - запуск эмулятора.

## 2. Описание всех функций и настроек

### Параметры командной строки

- `--vfs ПУТЬ` - путь к ZIP-архиву с VFS. Если параметр не задан или архив не удалось открыть,
  используется VFS по умолчанию (файлы `readme.txt`, `docs/guide.txt`, `bin/data.bin`).
- `--script ПУТЬ` - путь к стартовому скрипту.
- `-h` - краткая справка по параметрам.

При запуске в окно выводятся заданные параметры и сведения о VFS (количество файлов и каталогов).

### Стартовый скрипт

Текстовый файл, в котором каждая строка является командой эмулятора. Каждая строка
показывается в окне вместе с приглашением, затем выводится результат команды, как в диалоге
с пользователем. На первой ошибке скрипт останавливается и выводится строка
`ошибка в скрипте, строка N`. Если файл скрипта не найден, выводится сообщение об ошибке.
После скрипта окно остаётся открытым, команды можно вводить вручную.

### Ввод команд

Перед каждой введённой командой выводится приглашение с текущим каталогом VFS, например
`/docs$ ls`. Пустая строка игнорируется. Если кавычка не закрыта, выводится ошибка.
Об ошибках (неизвестная команда, неверные аргументы, несуществующий путь) эмулятор сообщает
строкой, которая начинается со слова `ошибка:`.

### Пути

Путь может быть абсолютным (`/docs/manuals`) или относительным (`docs/manuals`).
Поддерживаются `.` и `..`. Из корня `..` остаётся в корне.

### Двоичные данные

Файл считается двоичным, если он содержит нулевой байт или не читается как текст UTF-8.
Команды cat и head выводят такой файл в формате base64.

### Команды

- `ls [путь]` - выводит имена из каталога по одному в строке в алфавитном порядке. Для файла
  выводит его имя. Без пути показывает текущий каталог.
- `cd [путь]` - меняет текущий каталог. Без аргумента переходит в корень. Ошибка, если пути нет
  или это файл.
- `cat файл...` - выводит содержимое одного или нескольких файлов.
- `head [-n ЧИСЛО] файл` - выводит первые строки файла, по умолчанию 10.
- `touch файл...` - создаёт пустой файл в памяти. Существующий файл не меняется. Каталог, в
  котором создаётся файл, должен существовать. Архив на диске не изменяется.
- `date` - выводит текущие дату и время.
- `vfs-init` - заменяет текущую VFS на VFS по умолчанию, переходит в корень и удаляет файл
  архива, заданный параметром `--vfs`.
- `help` - выводит список команд с описанием.
- `exit` - закрывает окно эмулятора.

Команды `date`, `vfs-init`, `help` и `exit` не принимают аргументов, `ls` и `cd` принимают
не больше одного.

## 3. Команды для сборки проекта и запуска тестов

Сборка не нужна, программа запускается интерпретатором Python. Все команды выполняются
в корне проекта.

Запуск эмулятора:

```
python src\main.py
run.bat
```

Запуск с параметрами:

```
python src\main.py --vfs build\vfs_deep.zip --script scripts\start_stage4.txt
```

Создание тестовых ZIP-архивов (папка `build` создаётся автоматически и не хранится
в репозитории):

```
python tools\make_vfs.py
```

Скрипт создаёт три архива: `vfs_minimal.zip` (один файл), `vfs_several.zip` (три файла)
и `vfs_deep.zip` (четыре уровня вложенности и двоичный файл).

Автоматические тесты:

```
python -m unittest discover -s tests -v
```

Проверка стиля кода:

```
python -m pip install flake8
python -m flake8 --max-line-length=80 --max-complexity=10 src tools tests
```

Скрипты запуска для проверки находятся в папке `scripts`. Те из них, которым нужны архивы,
создают их сами перед запуском эмулятора:

- `test_no_params.bat` - запуск без параметров;
- `test_vfs_minimal.bat`, `test_vfs_several.bat`, `test_vfs_deep.bat` - разные варианты VFS;
- `test_vfs_missing.bat` - архив не существует;
- `test_vfs_init.bat` - команда vfs-init и ошибка в скрипте;
- `test_script_ok.bat`, `test_script_error.bat`, `test_script_missing.bat` - стартовый скрипт
  без ошибок, с ошибкой и несуществующий;
- `test_all_params.bat` - все параметры сразу;
- `test_stage4.bat`, `test_stage5.bat` - проверка всех команд, реализованных на 4 и 5 этапах.

## 4. Примеры использования

Запуск с глубокой VFS:

```
python tools\make_vfs.py
python src\main.py --vfs build\vfs_deep.zip
```

В окне появятся параметры запуска и сведения о VFS:

```
Параметры запуска:
  путь к VFS: build\vfs_deep.zip
  стартовый скрипт: не задан
VFS: файлов 6, каталогов 3
```

Работа с файлами и каталогами:

```
/$ ls
docs
readme.txt
/$ cd docs/manuals/deep
/docs/manuals/deep$ ls
data.bin
lines.txt
notes.txt
/docs/manuals/deep$ cat "notes.txt"
level 3
/docs/manuals/deep$ head -n 3 lines.txt
строка 1
строка 2
строка 3
/docs/manuals/deep$ cat data.bin
AAECAwQFBgcICQoLDA0ODw==
/docs/manuals/deep$ cd ../..
/docs$ cd
/$ date
Mon Oct  5 17:56:49 2026
```

Создание файлов (только в памяти):

```
/$ touch new.txt "my file.txt"
/$ ls
docs
my file.txt
new.txt
readme.txt
```

Список команд:

```
/$ help
ls [путь]               вывести содержимое каталога
cd [путь]               сменить текущий каталог
cat файл...             вывести содержимое файлов
head [-n ЧИСЛО] файл    вывести первые строки файла
touch файл...           создать пустой файл в памяти
date                    вывести текущие дату и время
vfs-init                заменить VFS на VFS по умолчанию
help                    показать список команд
exit                    закрыть эмулятор
```

Сообщения об ошибках:

```
/$ ls nope
ошибка: ls: nope: нет такого файла или каталога
/$ cd readme.txt
ошибка: cd: readme.txt: не является каталогом
/$ cat docs
ошибка: cat: docs: это каталог
/$ head -n x readme.txt
ошибка: head: использование: head [-n ЧИСЛО] файл
/$ touch nope/file.txt
ошибка: touch: nope/file.txt: нет такого файла или каталога
/$ abc
ошибка: неизвестная команда: abc
/$ cat "readme.txt
ошибка: незакрытая кавычка
```

Команда vfs-init заменяет VFS и удаляет файл архива:

```
/$ vfs-init
файл VFS удалён: build\vfs_deep.zip
VFS заменена на VFS по умолчанию
VFS: файлов 3, каталогов 2
```

Стартовый скрипт, остановившийся на ошибке:

```
python src\main.py --script scripts\start_error.txt
```

```
Параметры запуска:
  путь к VFS: не задан
  стартовый скрипт: scripts\start_error.txt
VFS: файлов 3, каталогов 2
/$ ls
bin
docs
readme.txt
/$ abc
ошибка: неизвестная команда: abc
ошибка в скрипте, строка 2
```
